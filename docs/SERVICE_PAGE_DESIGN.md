# 서비스 체험 페이지 디자인 규칙 v1

적용 대상: Clap Cat, 우사기 랩, 앞으로 추가할 상상자두 서비스 체험 페이지.

## 공통 구조

상상자두/서비스 헤더 → 소개 → 체험(`#experience`) → 3단계 사용 방법 → GitHub 소스·실행 안내(`#source`) → 다른 체험 → 출처 푸터 순서를 지킵니다. 부가 배너나 중복 다운로드 안내를 끼워 넣지 않습니다.

소개 버튼은 **웹에서 체험하기 ↓ / 소스·실행 안내 ↗**, 소스 카드 버튼은 **GitHub에서 소스 보기 ↗ / 실행 방법 보기 ↗**로 통일합니다. 소개의 두 번째 버튼은 페이지 안의 `#source`로 이동합니다. 소스 카드의 첫 링크는 해당 서비스 폴더, 두 번째 링크는 저장소 README의 공통 실행 안내를 가리킵니다.

## 공통 시각 규칙

`web/assets/toy-page.css`가 유일한 공통 스타일 소스입니다. 배경 #f6f3ed, 패널 #fffdf8, 본문 #28242c, 보조 #736c77, 경계 #dfd8df, 강조 #733c6b를 사용합니다. 기본 글꼴은 system-ui/Malgun Gothic입니다.

본문 최대 1200px(좌우 여백 포함), 데스크톱 여백 44px·모바일 22px, 섹션 간격 64px·모바일 40px입니다. 본문 16/14px, 안내 13px, 보조 12px이며 줄간격은 1.8~1.9입니다. 버튼 최소 높이 44px, 테두리 1px, 모서리 8px, 버튼 간격 12px을 기본으로 합니다. 소스 카드 모서리는 16px, 패딩은 32px/24px입니다.

750px 이하에서는 소개·사용 방법을 한 열로 배치하고, 소스 카드 버튼을 세로로 쌓습니다. 동일 제목·버튼·카드는 서비스별로 색·폰트·여백을 덮어쓰지 않습니다.

## 공유와 개별 영역

공통 템플릿: `templates/toys/page.html`. 서비스별 문구·출처·3단계 설명: `templates/toys/pages.json`. 서비스별 체험 DOM: `templates/toys/<slug>/experience.html`, 플로팅 등 추가 DOM: `extra.html`.

서비스별 `style.css`에는 고양이 플로팅·우사기 메모장처럼 조작에 필요한 스타일만 둡니다. header/main/footer/h1/공통 버튼/소스 카드 스타일을 개별 파일에 추가하지 않습니다. 새로운 공통 요구는 공유 템플릿과 CSS에 반영합니다.

## 작성·수정 절차

1. pages.json에 서비스 설명과 출처를 넣고 서비스 폴더에 experience.html·extra.html을 준비합니다. ID는 해당 앱 JavaScript가 사용하는 것과 일치시킵니다.
2. `python scripts/render-toy-pages.py`로 정적 HTML을 생성합니다. 생성된 index.html은 직접 수정하지 않습니다.
3. `python scripts/render-toy-pages.py --check`로 템플릿 일치를 확인합니다.
4. 데스크톱과 모바일에서 같은 위치의 버튼·정보 배치를 비교합니다. 체험 시작·입력/클릭·소리 제어·종료·키보드 포커스·가로 넘침을 확인합니다.
5. 현재 Cloudflare Pages 경로로 PR·배포하고 공개 URL에서 확인합니다.

## 기능·표기 원칙

버튼은 실제 가능한 동작만 제공합니다. 브라우저 고양이는 실제 로컬 Git push를 감지하지 않는다는 범위를 체험 바로 아래 표시합니다. 우사기의 입력당 길이, 정지·재개 설명은 현재 동작과 맞춥니다.

사이트 직접 다운로드는 두 서비스 모두 제공하지 않습니다. 다운로드 공개는 별도 사용자 지시가 있을 때만 바꿉니다. 출처·권리 표시는 푸터에 남깁니다. 고양이·우사기 이미지의 생성·변형으로 디자인을 맞추지 않습니다.
